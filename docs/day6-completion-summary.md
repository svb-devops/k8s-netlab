## 🔍 Day 6 问题发现与修复

### 实验10 问题

**问题:** 多容器 Pod 不指定容器时，描述为"会报错"
**实际行为:** 默认使用第一个容器，并显示提示信息 "Defaulted container..."
**修复:** 更新知识点描述为正确行为
**影响:** 低（不影响可执行性，仅描述有误）

### 实验11 问题1

**问题:** NODE_IP 获取命令返回 IPv4 和 IPv6 两个地址
**原因:** `jsonpath='{...addresses[?(@.type=="InternalIP")].address}'` 匹配所有 InternalIP 类型
**修复:** 改为 `jsonpath='{...addresses[0].address}'` 取第一个地址
**影响:** 高（导致验证脚本误报失败）

### 实验11 问题2

**问题:** Ingress 设置两条路径规则（`/` 和 `/api`），`/api` 直达 httpd 返回 404
**原因:** httpd 无 `/api/` 路径内容；nginx 的 `proxy_pass` 设计与 Ingress 双路由冲突
**修复:** 改为单路由（所有流量 → 前端 nginx），nginx 内部 `proxy_pass` 处理 `/api/`
**影响:** 高（实验步骤无法通过）

## 📚 技术总结

### Day 6 新增核心知识

**StatefulSet 三大保证:**
```
1. 稳定网络标识: <pod>.<svc>.<ns>.svc.cluster.local
2. 稳定持久存储: PVC 名称 = <template>-<pod-name>
3. 有序部署扩展: 创建 0→1→2，删除 2→1→0
```

**日志排查标准流程:**
```
1. kubectl get pod        → 看状态
2. kubectl describe pod   → 看 Events
3. kubectl logs           → 看应用日志
4. kubectl logs --previous → 看崩溃前日志
5. kubectl get events     → 看集群事件
```

**三层应用架构模式:**
```
Ingress → 前端(nginx) → 后端(httpd) → 数据库(redis)
ConfigMap: 应用配置
Secret: 数据库密码
PVC: 数据库持久化
Namespace: 项目隔离
```

### 关键发现

**1. NODE_IP 多地址问题**
- 节点可能同时有 IPv4 和 IPv6 InternalIP
- jsonpath filter 会返回所有匹配结果
- 应使用索引 `[0]` 而非 filter 确保只取一个

**2. Ingress + nginx proxy 设计模式**
- 双路由（Ingress 层和 nginx 层）会产生冲突
- 推荐单路由：所有流量进 nginx，nginx 内部负责转发
- 更贴近生产实际的单源部署模式
