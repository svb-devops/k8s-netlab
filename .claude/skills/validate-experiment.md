# validate-experiment

**触发时机**：用户新增或修改 `docs/experiments/` 下的实验文档时主动推荐。

验证实验文档质量，确保学生能顺利完成。

---

## 阶段一：结构完整性

读取目标文件，检查必须存在的 metadata 字段：

- `difficulty:` 字段（easy / medium / hard）
- `duration:` 字段（如 `30分钟`）
- `## 实验目标` 段落
- `## 前置条件` 段落
- 至少一个 `## 步骤` 或 `## 实验步骤` 段落
- `## 验证` 段落（验证学生是否真的完成）

缺少任意字段 → 列出缺失项，要求补充后重新验证。

---

## 阶段二：命令可执行性检查

扫描文档中所有代码块里的 `kubectl` 命令：

```bash
grep -A2 '```bash' docs/experiments/<file> | grep kubectl
```

对每条 kubectl 命令：
- 检查是否使用了本实验未创建的资源名（前向依赖）
- 检查是否依赖特定命名空间（需在前置条件中声明）
- 检查镜像名是否在常用列表内（nginx、busybox、alpine — 本地 registry 已有）

---

## 阶段三：编号和文件名

- 文件名格式：`NN-slug.md`（两位数字 + 连字符 + 小写）
- 编号与现有文件不冲突
- slug 不含下划线

---

## 阶段四：与模板对比

读取 `docs/experiments/template.md`，对比目标文件结构，报告：
- 模板有但目标文件缺少的段落
- 目标文件有但不符合模板规范的格式

---

## 输出

每个阶段报告通过/失败，最后给出：
- 质量评分（通过阶段数 / 4）
- 具体修改建议（如有）
- `✅ 可以合入` 或 `❌ 需要修改后重新验证`
