# 触发条件：重构代码（不改行为）

适用场景：提取硬编码值到 config、改名、移动代码、拆分函数——**不改可观测行为**。

**铁律：先写测试证明旧行为，再改代码，改完跑全量。**

---

## 步骤（不得跳步）

1. **读所有受影响的代码和调用点**，精确确定改动边界
2. **做纯加法预备**（如加 config 变量、加常量），此步不改任何已有行为，全量测试仍然全通过
3. **写回归测试**，描述"改完后的预期行为"，此时测试必须 **FAIL**（证明旧行为被观测到了）
4. **做最小改动**，让新测试通过
5. **跑全量测试**：
   ```bash
   source venv/bin/activate && pytest tests/ -x -q --tb=short --cov=backend --cov-report=term-missing
   ```
6. **修所有因改动而 fail 的现有测试**（常见原因：测试 mock 了整个 config 模块但没声明新字段）
7. **再跑全量**，全部通过才提交
8. 更新 `CHANGELOG.md` `[Unreleased]` 段：`- refactor: <描述>`
9. commit + push

---

## 不允许

- 跳过步骤 3（不写失败测试直接改代码）
- 只跑相关测试、不跑全量就提交（副作用只有全量才能发现）
- 把多个不相关的重构打包进一次提交

---

## 下一步推荐

- 全量测试通过 → commit，message 格式：`refactor: <描述>`
- 发现测试因 mock 整个 config 而脆弱 → 在修副作用时顺手补齐 mock 字段，勿忽略
